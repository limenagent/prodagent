# 示例导览：每个例子在演示什么

所有示例都用 `ScriptedLlm` 按脚本扮演模型，**离线、零成本、结果确定**。在仓库根目录这样运行：

```bash
PYTHONPATH=. python examples/文件名.py
```

建议按上面列出的顺序读，它们是一条由浅入深的爬坡路线。括号里是你读代码时最该观察的东西。

## 先看两个“纯内核”例子

- **graph_demo.py**：不用任何模型，直接用 Plan/Node/Edge/Scheduler 跑一张图。重点看波次怎么一轮轮
  推进、状态怎么在屏障处折叠。这是理解引擎的最短路径。
- **react_demo.py**：用最朴素的内核原语，手工拼出一个 ReAct 循环。重点看 think⇄act 的回边是怎么
  用一条 `Goto` 实现的——看完你会明白 ReAct 真的不是框架特供。

## 再看由浅入深的业务例子

- **greeter.py**：最小的门面用法，一个 Agent + 一个工具。观察 `Agent.run()` 底下其实还是那张图。
- **trader.py**：多轮砍价，写操作前要过一道人工审批门，外加跨轮记忆。观察 `wait_human` 如何让
  运行真正挂起、`resume` 如何从断点继续。
- **deep_research.py**：连续多轮检索，并触发上下文的五级压缩。观察上下文不是内存，而是每次现场
  装配出来的投影。
- **compliance_audit.py**：多个核查步骤并行，其中一个被审批拒绝时，其余结论不被推倒。观察波次
  并发与“错误是反馈、可以再改”的处理。
- **code_detective.py**：接入一个 MCP 工具、从磁盘加载一份技能（Skill），工具失败后让模型自己
  修正。观察 MCP 工具如何在边界被归一化成普通工具。
- **after_sales.py**：主管 Agent 的“工具”是别的 Agent：先派账单专家拿回事实、再派风控专家拿回
  结论，最后自己决定。观察每次委派都是“去了要回来”（call），以及风控再往下委派长出的三层树。
- **aiops.py**：诊断节点用 call 要返回结果，决定转交给修复节点时用 transfer——同图 `go`、不画
  回边，控制权一去不返。对比这两种多 Agent 汇合语义的差别。
- **handoff.py**：流程里没有主管的纯 *transfer*，两种形态——固定交接**链**
  （triage → billing → risk → close），以及同伴可以把案子**退回**（billing ↔ risk）
  再了结的**蜂群网**。图上只登记 Agent 节点、节点之间一条边都不画：下一任持有者
  是专家在自己的判决里用运行时 `go` 指定的。观察控制权一去不返、只有一行摘要向前传递。
- **write_review.py**：撰稿 Agent 出稿、审阅 Agent 挑错，没通过的审阅意见被条件分支带回修订 Agent
  回炉，通过则直接定稿。观察质量迭代就是一条普通的带回边的循环，节点里坐的是 Agent。
- **orchestrator.py**：编排者-工人。图上只有一个 reviewer 节点，规划 Agent 先调目录工具看现状、
  输出编号计划，每行被 `Send` 压出一份模板拷贝——同一波并发，`join="all"` 等齐全部再汇总。观察
  扇出宽度是运行时数据，不是画死的图。
- **blackboard.py**：黑板共识。专家之间互不调用，只往共享 append 通道追加意见；裁判 `join="all"`
  等齐本轮每人一条，读整块板裁决，未收敛就 `Goto.rejoin` 重开一轮。观察意见只增不删、多轮累积。
- **dating_chat.py**（压轴验证场景）：Agent 相亲——同一个共享对话里的两种上下文管理。大牛手搓
  messages 列表、原文转发工具大结果、超阈值就 `del messages[:-4]`；
  小美跑在框架上：预埋长期记忆（think 前召回注入 system）+ 五级压缩管理六条消息的窗口。她自己查评价
  识破陷阱——压缩结果头部的海鲜证据和尾部的吵闹评价都还在——复盘对照三个布尔：她的摘要仍记得
  海鲜过敏，大牛的窗口早把它删没了。

## 最后看三类“生产能力”例子

- **persistence.py**：检查点落盘后，换一个全新进程也能从断点恢复。观察 Run 快照里到底存了什么、
  哪些活对象（连接、凭证）不参与序列化。
- **retry_timeout.py**：给节点设超时和指数退避重试。观察“超时算一次失败、是否重试是可替换策略”。
- **backpressure.py**：节点边算边通过 Bus 吐高频事件，订阅端用有界队列做 block/drop 背压。观察
  背压如何把压力一路传回生产端。

记忆的附加场景；11–13 的机制演示请在终端跑），右侧是同一条 Bus 上的事件时间线，并行、挂起审批、
委派与接力都肉眼可见。它和这些示例用的是同一套内核，只是把过程画了出来。
