# 术语表

按你在阅读中遇到的先后排列，每个词给一句大白话和它在代码里的位置。

## 内核机制

**Plan（蓝图）**：一张静态的执行图纸，写清有哪些节点、怎么连、状态有哪些通道。可复用、可分析。
见 `kernel/graph.py`。

**Node（节点）**：图里的一个步骤。它本身只是个位置，真正干活的是它的 body。

**Edge（边）**：节点之间的有向连线，可以带条件 `when`。边描述“谁完成后谁才有机会就绪”。

**Channel（状态通道）**：一个有名字的状态字段，外加一条合并规则。并发写同一个字段时，按这条规则
确定地合并，而不是互相覆盖。

**reducer（合并规则）**：`(旧值, 新值) -> 合并值` 的纯函数。内置四种：`last` 后写覆盖、`append`
追加为列表、`add` 数值相加、`merge` 字典合并。

**Run（一次执行）**：某张 Plan 的一次具体运行，携带当前状态、每个节点跑到哪、父子关系。一次性、
可序列化。

**body（节点执行体）**：节点真正干活的部分，可以是普通函数、一次工具调用、一次模型调用，或递归
激活一张子图。内核只认“它能被调度执行”这一个接口。

**Outcome（执行结果）**：body 的产出，正交地分成给下游的值 `value`、写状态的 `state_delta`、控制
命令 `control`、以及暂停请求 `suspend`。

**Command（控制命令）**：节点对调度器说“下一波怎么走”。只有两种：`Goto` 重新武装某个节点（回边、
跳转、交接都靠它），`Send` 在运行时实例化一个模板节点（动态扇出）。

**Scheduler（调度器）**：唯一的引擎，循环做三件事——算就绪、波次并发、屏障折叠并落检查点。

**就绪集合（ready set）**：当前这一波，前置条件都满足、可以立即执行的节点集合。

**波次 / 超步（wave / superstep）**：“算齐一批 → 并发执行 → 屏障统一提交”算一波。波次是一致性边界。

**屏障（barrier）**：一波节点全部结束的那个同步点，状态在这里统一折叠、命令在这里统一应用。

**Event（事件）**：“已经发生的事实”，不可变、只追加。当前状态是事件流折叠出的投影。

**EventLog（事件日志）**：事件的唯一事实源，append-only。审计、恢复、时间旅行都靠重放它。

**Checkpoint（检查点）**：在波次边界给 Run 拍的快照，用于快速恢复；它是可丢弃的缓存，真相仍在事件里。

**Bus（事件总线）**：内核对外的唯一接缝，有三个协议——`fire` 旁观广播、`check` 裁决把关、`subscribe` 订阅事件流；
其中订阅是有界队列，用 `block`/`drop` 两种策略支撑流式和背压。

**背压（backpressure）**：下游消费不过来时，把压力传回上游（`block` 等待）或主动丢帧计数（`drop`），
避免内存被无限撑爆。

**Interrupt（中断/挂起）**：节点在任意位置请求“先停下、等人或等外部”，框架落盘并放手；之后外部
`resume` 推一把，从断点原样继续。

**Port（端口）**：内核与外部世界之间的协议接口（模型、工具、子 Agent、存储）。内核只认识端口，
具体实现从外部注入，测试时换成脚本化的 Fake，于是能离线、确定性地跑。

## 上层策略

**ReAct**：“想一步、做一步、再想”的循环。在本项目里它不是内核类，而是 think/act 两个节点加一条
回边拼出的配方。

**plan-first（先规划后执行）**：模型先产出一份步骤清单（它只是状态里的数据，不是执行图），再动态
扇出执行、最后汇总。

**call（委派）**：父节点激活一个子 Run，子干完把结果交回，父继续；控制权一定返回。

**transfer（接力 / handoff）**：同一张图里 `go` 到另一个 Agent 节点且不画回边，控制权一去不返。

**blackboard（黑板）**：多个 Agent 不直接互调，而是共写一组共享通道，谁发现数据齐了谁就动。

**Agent / Workflow（门面）**：内核原语之上的好用封装。Agent 是会自主思考、用工具、能派活的对象；
Workflow 是声明式流程图。九成场景用门面，需要深度定制再下沉到原语。
