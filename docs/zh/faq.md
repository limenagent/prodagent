# 常见问题

## 它和 LangGraph 是什么关系？要替代它吗？

不替代，是互补。LangGraph 是功能完整、生态丰富的生产框架；prodagent 是一个小到能在周末从头读完的
**参照实现**，用最少代码把“图、状态、调度、事件、中断、多 Agent”这套共同的内核讲清楚。概念对应见
[对照表](comparison.md)。很多人的用法是：先读本项目把原理吃透，再回到 LangGraph 高效干活。

## 为什么运行时零三方依赖？做得到吗？

做得到。内核只用 Python 标准库：并发用 `asyncio`，持久化用文件原子写，Playground 用 `http.server`。
这样做是为了让你读内核时不被第三方框架的魔法打断，也让离线测试又快又稳。接真实模型时，
`openai_lite.py` 同样只用标准库直连 OpenAI 兼容接口，不引 SDK。

## 需要 API Key 吗？要花钱吗？

跑示例、跑测试、玩 Playground **都不需要**。它们用 `ScriptedLlm` 按脚本扮演模型，结果确定、可反复
运行。只有你想接真实大模型时，才设置 `OPENAI_API_KEY`（可选 `OPENAI_BASE_URL`、`OPENAI_MODEL`）。

## 零基础能学吗？需要先会哪个框架吗？

不需要先会任何 Agent 框架，但建议你能看懂基本的 Python（函数、类、`async/await`）。学习路径就是
[文档导览](README.md)那条线：先读架构总览建立全貌，再看五篇设计说明，最后对照 `examples/` 和
`tests/`。术语第一次出现都会用大白话解释，也可以随时查[术语表](glossary.md)。

## 这门课/这个项目说的“生产级”是什么意思？

这里的“生产级”指**框架内核具备明确的执行语义**：状态可持久化、故障可恢复、并发结果确定、能暂停等人
审批、有清晰的扩展边界。它不是一套开箱即用的企业平台——多租户、分布式集群调度、模型评测、业务治理
后台这些不在范围内。教学版默认单进程、文件持久化；把存储等端口换成数据库实现，是清晰预留好的扩展，
但项目本身不替你做完。

## 为什么内核里没有 ReAct / 没有“运行模式枚举”？

因为这些是**策略**，不是**机制**。ReAct、plan-first、多 Agent 都是用同一小把原语在上层拼出来的，
内核只提供中立的节点、边、命令和调度。详见[设计说明 04](design/04-no-pattern-in-kernel.md)。

## 为什么没有 Turn 这类概念？

设计上刻意追求“概念最少、彼此正交”。凡是能被已有原语吸收的概念，就不单独设立。类似“一轮对话/一次
工具批处理的边界”，在这套内核里由“节点 + 波次 + state_delta”自然表达，不需要再引入一个独立名词。
概念越少，内核越稳，也越好学。

## 多 Agent 真的不用新引擎吗？

不用。一个 Agent 调另一个，本质是某个节点的 body 递归激活了一张子图（子 Run），用的还是同一个
调度器。要区分的只是控制流（委派要返回 / 接力不返回 / 黑板共享）和状态（隔离 / 共享）这两条正交的轴。
详见[设计说明 05](design/05-multi-agent.md)。

## 出错了怎么办？哪里可以提问？

- 先看对应设计说明和 `tests/` 里同名的测试——测试是最小、最确定的“用法示例”。
- 仍不清楚，欢迎到 GitHub 提 issue，选择 “Learning question” 模板。学习时卡住的地方，对教学项目
  来说也算需要修的问题。

## 和极客时间专栏《生产级 Agent 框架设计与实现》什么关系？

这个仓库是专栏的配套代码，也是专栏推导的最终落地。文档讲清“是什么、为什么这么取舍”，专栏则从六行
循环开始，一步一步带你把这些代码亲手写出来，包含每一步的推演过程、被否决的方案和踩坑细节。简单说：
文档是地图和风景，专栏是全程导游。
