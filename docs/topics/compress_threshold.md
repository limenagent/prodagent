# LLM Agent 上下文压缩最优触发点：完整数学建模与多厂商数值分析

## 一、问题定义

### 1.1 业务场景

在 LLM Agent（如 Tool Calling、多轮对话）中，上下文随轮次线性增长。面临两种策略：

- **Append-Only（不压缩）**：每轮把完整历史塞给模型，依赖前缀缓存降低成本
- **Summarization（压缩）**：每隔 N 轮对历史做摘要压缩，缩短上下文但产生一次性开销

### 1.2 核心问题

> 在 1M 上下文窗口下，上下文长度达到多少时触发压缩，能使**每轮平均成本最低**？

### 1.3 决策变量与约束

- 决策变量：压缩间隔轮次 $N$（或等价地，触发长度 $L$）
- 约束：触发长度 $L \leq$ 模型最大上下文窗口（本文为 1M）
- 优化目标：最小化每轮平均成本 $C_{\text{avg}}(N)$

---

## 二、问题分析

### 2.1 成本结构拆解

一个压缩周期内的成本由三部分构成：

| 成本项 | 计费方式 | 与 N 的关系 |
|:---|:---|:---|
| 压缩调用 | 全价读取上下文 + 生成摘要（输出） | 固定开销，随 N 增大摊薄 |
| 压缩后第 1 轮 | 新前缀未建立缓存，全价 | 固定开销 |
| 第 2~N 轮 | 前缀命中（折扣价）+ 新增未命中（全价） | 前缀随 N 增长，命中成本累积 |

### 2.2 核心权衡（EOQ 结构）

$$\underbrace{\frac{B}{N}}_{\text{压缩开销摊薄}} \quad \text{vs} \quad \underbrace{\frac{rd}{2} \cdot N}_{\text{长尾前缀累积}}$$

- $N$ 太小：压缩频繁，一次性开销摊不薄
- $N$ 太大：上下文太长，即使命中价便宜，基数大导致总成本上升
- 两者平衡点即为最优解

### 2.3 关键假设（修正版）

本文采用比原文更符合实际的假设：

1. **System Prompt $S$ 始终命中**：RadixAttention 按前缀匹配，固定系统提示在每个请求中都是前缀，始终享受缓存价
2. **压缩调用**：$S$ 命中，历史+模板未命中（压缩请求结构与正常交互不同，前缀在 $S$ 后断开）
3. **压缩后第 1 轮**：$S$ 命中，新摘要 $A$ 和新增 $d$ 未命中
4. **第 2~N 轮**：前缀 $S+A+(k-1)d$ 已建立缓存，全部命中；新增 $d$ 未命中

> **与原文的差异**：原文假设压缩调用和第 1 轮"100% 未命中"（连 $S$ 都全价），这是过度悲观的简化。修正后 $S$ 始终命中，更接近 vLLM/SGLang/DeepSeek 实际的 RadixAttention 机制。

## 三、数学建模

### 3.1 符号定义

| 符号 | 含义 | 典型值 |
|:---|:---|:---|
| $S$ | 固定系统前缀长度 | 10,000 |
| $A$ | 压缩后摘要长度 | 2,000 |
| $d$ | 每轮净增上下文（输入+输出+工具返回） | 5,000 |
| $M$ | 压缩指令模板长度 | 500 |
| $N$ | 两次压缩之间的轮次数（决策变量） | — |
| $C_i$ | 输入未命中单价 | 模型相关 |
| $r$ | 缓存命中折扣率（命中价 = $r \cdot C_i$） | 0.02~0.5 |
| $q$ | 输出/输入价格比（$C_o = q \cdot C_i$） | 3~5 |

### 3.2 逐项成本函数

**压缩调用**（触发时上下文 = $S + A + Nd$）：

$$\text{Cost}_{\text{compress}} = \underbrace{S \cdot rC_i}_{S\text{命中}} + \underbrace{(A + Nd + M) \cdot C_i}_{\text{历史+模板未命中}} + \underbrace{A \cdot qC_i}_{\text{生成摘要（输出）}}$$

**压缩后第 1 轮**：

$$\text{Cost}_1 = \underbrace{S \cdot rC_i}_{S\text{命中}} + \underbrace{(A + d) \cdot C_i}_{A\text{和新增}d\text{未命中}}$$

**第 $k$ 轮（$k \geq 2$）**：

$$\text{Cost}_k = \underbrace{[S + A + (k-1)d] \cdot rC_i}_{\text{前缀命中}} + \underbrace{d \cdot C_i}_{\text{新增未命中}}$$

## 四、数学推导

### 4.1 周期总成本

一个周期 = 1 次压缩 + $N$ 轮交互：

$$\text{Cost}_{\text{cycle}} = \text{Cost}_{\text{compress}} + \text{Cost}_1 + \sum_{k=2}^{N} \text{Cost}_k$$

展开并按 $N$ 的幂次合并（提取公因子 $C_i$）：

**$N^2$ 项**（来自前缀命中的累加 $\sum_{k=2}^{N} r(k-1)d$）：

$$\frac{rd}{2} N^2$$

**$N$ 一次项**（来自压缩中的 $Nd$、第 1 轮的 $d$、第 2~N 轮的 $(N-1)d$、前缀中的 $r(N-1)(S+A)$，以及 $N^2$ 项展开的 $-\frac{rd}{2}N$）：

$$N \cdot \Big[ r(S+A) + 2d - \frac{rd}{2} \Big]$$

**常数项**（与 $N$ 无关）：

$$B = rS + A(2+q-r) + M$$

因此：

$$\boxed{\text{Cost}_{\text{cycle}} = C_i \cdot \left[ \frac{rd}{2} N^2 + \Big(r(S+A) + 2d - \frac{rd}{2}\Big) N + B \right]}$$

### 4.2 平均成本与求导

每轮平均成本：

$$C_{\text{avg}}(N) = \frac{\text{Cost}_{\text{cycle}}}{N} = C_i \cdot \left[ \frac{rd}{2} N + \Big(r(S+A) + 2d - \frac{rd}{2}\Big) + \frac{B}{N} \right]$$

中间的一次项系数是常数，求导时消失。对 $N$ 求导并令其为 0：

$$\frac{d C_{\text{avg}}}{dN} = C_i \cdot \left( \frac{rd}{2} - \frac{B}{N^2} \right) = 0$$

### 4.3 最优解

$$\boxed{N^* = \sqrt{\frac{2B}{rd}}}$$

二阶导数 $f''(N) = \frac{2B}{N^3} > 0$，确认为全局最小值。

### 4.4 触发长度

触发压缩时的上下文总长度 = 固定前缀 + 摘要 + $N$ 轮累积：

$$L^* = S + A + N^* \cdot d$$

代入 $N^*$：

$$\boxed{L^* = S + A + \sqrt{\frac{2Bd}{r}}}$$

其中 $B = rS + A(2+q-r) + M$，展开得：

$$\boxed{L^* = S + A + \sqrt{\frac{2d}{r} \cdot \big[ rS + A(2+q-r) + M \big]}}$$

### 4.5 窗口约束

若 $L^* \leq W$（窗口大小），则无约束最优解可行；若 $L^* > W$，则在窗口满之前达不到最优触发点，压缩不经济。

### 5.4 关键观察

1. **缓存折扣越大（$r$ 越小），最优触发点越靠后**：DeepSeek（r=0.03）在 72k 触发，GPT-4o（r=0.5）在 30k 就该压缩
2. **所有厂商的最优触发点都远小于 1M 窗口**：最高的 DeepSeek 也只用到 7.2% 的窗口
3. **$r$ 是最敏感的参数**：从 0.03 到 0.5，触发点从 72k 降到 30k，差 2.4 倍
4. **1M 窗口约束对所有厂商都不生效**：$L^* \ll 1M$，无约束最优解全部可行

## 六、结论

### 6.1 1M 窗口下的最优压缩触发点

| 如果你用的是 | 在上下文达到这么长时压缩 | 约对应多少轮 |
|:---|:---:|:---:|
| **DeepSeek V4 Flash** | **~72k** | ~12 轮 |
| Claude Sonnet 5 / Gemini 3 / Kimi K3 | **~51k** | ~8 轮 |
| GPT-4.1 / GLM-5.2 / Qwen | **~36~37k** | ~5 轮 |
| GPT-4o | **~30k** | ~4 轮 |

### 6.2 核心结论

> **在 1M 上下文窗口下，所有主流模型的最优压缩触发点都在 30k~72k 之间，远低于窗口上限。缓存折扣越大的模型（如 DeepSeek），触发点越靠后；缓存折扣小的模型（如 GPT-4o），触发点越靠前。**

### 6.3 落地建议

1. **不要等窗口快满才压缩**：1M 窗口下，最优触发点最高才 72k（DeepSeek），等到 500k 再压缩，平均成本比最优值高 3~4 倍
2. **按模型定价调参**：同一个 Agent 系统，用 DeepSeek 和用 GPT-4o 的最优触发点差 2.4 倍，不要用一个阈值打天下
3. **短对话（<最优轮次）不需要压缩**：如果你的 Agent 任务平均 5 轮内结束，压缩的一次性开销根本摊不薄，直接不压缩更划算
4. **高准确率场景优先外部记忆**：以上是纯金钱成本最优。压缩是有损的，90k→12k 丢 87% 信息，如果任务依赖早期历史（代码、金融、多步推理），用 RAG/向量库存关键信息比在上下文里硬压缩更可靠
5. **用真实日志重算 $d$**：本文用 d=5k（输入 2k+输出 3k）作为典型值，但你的业务可能不同。$d$ 越大，触发点越靠后；$d$ 越小，触发点越靠前。上线前用真实 Agent 轨迹日志统计 P95 的每轮净增 token，代入公式 $L^* = S + A + \sqrt{\frac{2d}{r}[rS + A(2+q-r) + M]}$ 即可得到你的专属阈值。

### 6.4 公式速查

$$\boxed{L^* = S + A + \sqrt{\frac{2d}{r} \cdot \big[ rS + A(2+q-r) + M \big]}}$$

代入你的模型参数（$r, q$）和业务参数（$S, A, d, M$），立即得到最优触发长度。
