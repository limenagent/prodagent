# 合规审计

---

> 示例 #4 —— Agent 审计交易流水、提交可疑活动报告：写操作要人批准，被拒后只换动作不推倒重来。

每天早上，银行的合规分析师要做同一件事：把昨天几万笔交易过一遍，挑出可疑的——大额拆分、
汇向开曼的壳公司、卡在申报阈值边上的小额兑换——再写成一份 SAR（可疑活动报告）报给监管。
手工干又慢又容易漏。

这个例子把这件事交给一个 Agent。它的打算很清楚：先把交易拉出来，再同时做两件事——标出哪些
可疑、把相关账户串起来看；最后综合成一份 SAR，提交给监管。

但真到了"提交"那一下，它不会替你做主。提交监管是不可逆的外部动作，所以 Agent 会停下来弹一
个审批框：这份报告，交不交出去？

- 你点**批准**，Agent 替你提交，完事。
- 你点**拒绝**，Agent 不硬来，也不推倒重来。前面已经抽好的交易、标好的可疑、串好的账户全都
  留着——它只换一个动作：不自动提交了，改成把这份报告草拟出来，交给你再人工核一遍。

这就是第八课想说的那种 Agent：计划看得见、改得动，撞墙了只局部改道，而不是蒙眼狂奔、撞墙
重来。

## 本示例展示什么

- **自己拆活、排顺序**：拿到"审计今天的交易"，Agent 自己拆成"抽取 → 标注/关联 → 提交"，还
  知道标注和关联这两步可以同时做。
- **写操作要人批准**：提交监管这种收不回的动作，执行前必须人点一下头。
- **被拒后不推倒重来**：拒绝只让 Agent 换个动作（改成草拟报告转人工复核），已经做完的分析
  一步都不重跑。
- **不会重复提交**：同一份报告哪怕重试，也只交一次。
- **崩了能续跑**：中途挂掉，重启后从断点接着干，不从头来。


## 一条审批，两种结局

```
"审计今日交易流水"
  → 抽出 5 笔交易
  → 同时做两件事：标出 3 笔可疑  ‖  串起壳公司 / 加密兑换两组账户
  → 综合成一份 SAR，准备提交监管
  → 弹审批框

  批准 → 提交 SAR，完成
  拒绝 → 不重提交，改成草拟报告转人工复核，完成
         （前面三步全保留，一步都不重跑）
```

## 和 ReAct 的对照

第八课开篇那场灾备迁移灾难，根子是 ReAct 模式下计划藏在模型脑子里、系统看不见，一步失败就
可能整盘重来。本例换了个活法：

| | 蒙眼狂奔的 ReAct | 本例 |
|---|---|---|
| 计划看得见吗 | 藏在模型脑子里，做完就忘 | 是一份能看、带版本号的清单 |
| 一步失败 | 模型临时决定，可能整盘重来 | 系统只换掉坏的那步，别的都留着 |
| 收不回的动作 | 模型直接做 | 先弹框问人 |
| 谁在驱动 | 模型走一步看一步 | 系统照着计划走 |

想看怎么实现的：声明一个"高危、要审批"的工具，只要标个 HIGH（见 `tools.py` 里的
`submit_to_regulator`）；被拒后换动作的兜底，是同文件里的 `draft_sar_for_review`。完整逻辑
在 `agent.py`。
