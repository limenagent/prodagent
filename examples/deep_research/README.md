# 深度研究

---

> 示例 #3 —— 让 Agent 连查十几轮资料写报告，最容易翻车的不是搜索，是跑到后面把第一轮的数字忘了。

让 Agent 做深度研究，真正的坑往往不是搜不到，而是上下文。它一连查十来轮，每轮结果几千
字往对话里塞，查到第六轮，第一轮查到的关键数字已经被挤出去了。你让它写报告，它把第三轮
的结论安到第八轮的数据上——不是模型蠢，是窗口被撑爆后早期信号没了。

一种省事的做法是直接砍：只留最近几条消息。问题是它可能再也想不起研究一开始的关键发现，
报告后半段就开始编。

这个例子演示另一种活法：历史撑爆窗口时，框架自动把早期对话总结成摘要，关键数字留下，
该引用还能引用。于是它跑完十几轮，写报告时还能准确说出第一轮查到的那个数——因为压缩
没把核心信号一起丢掉。

## 本示例展示什么

- **一轮一轮查**：看完上一条结果，才决定下一条查什么。研究本来就是这样的——你不知道下
  一步查啥，直到你看完上一步。
- **不会越查越失忆**：历史爆窗口时自动把早期对话压成摘要，关键数字不丢，长跑也不胡编。
- **带着流程手册**：先加载一份"怎么做研究"的手册照着走，不用每次重新摸索。

让它长跑而不失忆，靠的是框架，不是 prompt。代码在 `agent.py`。
